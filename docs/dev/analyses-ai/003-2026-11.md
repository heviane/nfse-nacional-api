# Análise do `nfse-nacional-api` (09/11/2026)

## 🔴 Alto

### 1. Escape da resposta SOAP diverge do contrato documentado

O `cliente-001-servico-legado.md` (seção 4.2) mostra `XmlNfse` com **escape duplo** (`&amp;lt;NFSe…`), mas `montarRespostaSoapSucesso` aplica só um `replace("<","&lt;")`. Depois que o GeneXus decodifica o envelope, `RetornoEmissao` chega assim:

- `<XmlNfse>` contém **elementos filhos** `<NFSe>…`, e não uma string.
- Se a NFS-e tiver `&amp;` no texto (ex.: "A & B"), o `&` vira cru e o XML interno fica malformado.
- O mesmo vale para `MotivoStatus` no erro de `<Rps>`: o `<Rps>` vira elemento dentro do texto.

Os testes só usam `containsString("&lt;Sucesso&gt;…")`, então nada pega isso. A correção é montar o XML interno com `escapeXml` nos valores e escapar o conjunto uma vez:

```java
String interno = "<RetornoEmissao>"
    + "<Sucesso>" + sucesso + "</Sucesso>"
    + "<CodigoStatus>" + status + "</CodigoStatus>"
    + "<MotivoStatus>" + escapeXml(motivo) + "</MotivoStatus>"
    + "<ChaveAcesso>" + chave + "</ChaveAcesso>"
    + "<XmlNfse>" + escapeXml(xmlNfse) + "</XmlNfse>"
    + "</RetornoEmissao>";
String result = escapeXml(interno);   // vai dentro de <GerarNfseResult>
```

O teste do `<Rps>` passa a esperar `&amp;lt;Rps&amp;gt;`. Mesmo assim, valide com o retorno real da SIL (o `retorno_SUCESSO.xml` histórico) antes de fechar: o que o GeneXus espera é a fonte da verdade.

### 2. `executarComRetry` engole exceções de domínio e vira 502

No `SefinClientAdapter`, o `catch (Exception e)` genérico embrulha em `SefinTransmissaoException` tudo o que o lambda lança. Isso inclui `ValidacaoFiscalException` (XSD do `pedRegEvento`) e `AssinaturaDigitalException`. Resultado: um `cMotivo="3"` ou um `xMotivo` com quebra de linha ou caractere fora de `[!-ÿ]` retorna **502 "Erro durante Cancelamento…"**, quando deveria ser 422. Adicione antes do catch genérico:

```java
} catch (ValidacaoFiscalException | AssinaturaDigitalException | IllegalArgumentException e) {
    throw e;
}
```

Acrescente um teste de cancelamento com motivo inválido esperando `ValidacaoFiscalException`. Valide também no `RequisicaoCancelamentoDps` que `codigoMotivo ∈ {1,2,9}` e que `motivo` tem no máximo 255 caracteres, hoje só o mínimo de 15 é checado.

### 3. Ambiente: o servidor não é a autoridade

- `RequisicaoCancelamentoDps` (e `ConsultaNfseController`) usam **HOMOLOGACAO como default** quando `ambiente` vem nulo. Num servidor configurado com `NFSE_ENVIRONMENT=PRODUCAO`, um cancelamento sem `ambiente` vai silenciosamente para homologação.
- No REST de emissão, `request.ambiente()` **sobrepõe** a configuração do servidor, então um cliente consegue emitir em PRODUÇÃO num servidor de homologação. O SOAP usa o servidor, então os dois caminhos divergem.

Pela regra 11 do `AGENTS.md`, sugiro: ambiente = `nfseProperties.resolverAmbiente()`; se o request informar outro, rejeitar com 422 e mensagem clara (como já é feito com `tpAmb`). Isso elimina o default silencioso nos três casos de uso.

### 4. Roteiro de homologação e script têm payload e rotas inválidos

O `roteiro-homologacao-sefin-nacional.md` e o `test-homologacao-sefin.ps1.example` são o primeiro teste real, e hoje falhariam:

| Problema                                                                  | Onde                                                                    |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `<valores>` **dentro de `<serv>`** (no XSD é irmão de `serv`)             | roteiro e script                                                        |
| `<ender>` em vez de `<end>` no tomador                                    | roteiro e script                                                        |
| Faltam `serie`, `nDPS`, `tpEmit` e `cLocEmi` (obrigatórios)               | roteiro e script                                                        |
| `cLocIncid`, `vBC` e `vISSQN` dentro de `tribMun` (não existem no schema) | roteiro e script                                                        |
| `POST /api/v1/dps` e `/api/v1/nfse/{chave}/cancelar`                      | o real é `/api/v1/dps/emitir` e `/api/v1/nfse/cancelar` (chave no body) |
| URL `sefin.hom.nfse.gov.br`                                               | o código usa `sefin.producaorestrita.nfse.gov.br`                       |
| Id `DPS32052002601…` (formato de chave)                                   | não bate com o prestador                                                |

Além disso, `emissao-sefin.md`, `manual-execucao-local` e `cliente-001-servico-legado` usam Id com tipoInsc **`2` (CPF)** para um CNPJ. O Sefin valida o Id contra o prestador, então rejeitaria. Basta apontar esses documentos para o `payload-emissao-rest.json` (que já usa tipo `1`), que passa no XSD.

## 🟠 Médio

### 5. Coerência do Id da DPS não é verificada no fluxo

`DpsIdHelper` existe e é testado, mas nenhum serviço o usa. Sugiro uma validação **sem mutação**, em linha com a regra 11, dentro do `EmitirDpsService`. O Id deve bater com `cLocEmi`, o tipo e documento de `prest` (CNPJ ou CPF com zeros à esquerda), `serie` (5 dígitos) e `nDPS` (15 dígitos). Qualquer divergência vira `ValidacaoFiscalException` explicando o campo. O `dps-exemplo-valido.xml` seria pego: Id com CPF e série `00900`, enquanto o corpo tem CNPJ e série `00001`. Ajuste o sample e o teste do assinador que depende da URI.

### 6. Mensagens de erro

- `RestExceptionHandler.handleIllegalState` devolve `ex.getMessage()` com o **caminho do certificado no servidor** ("não encontrado em /opt/certs/…") e status 400. É falha de configuração do servidor (500/503), e o caminho não deve sair.
- `SefinTransmissaoException` embute o **corpo bruto do Sefin** na mensagem, que vai ao cliente e ao log de auditoria. Devolva uma mensagem curta e deixe o corpo só em log nível DEBUG.
- `ValidacaoFiscalException` já concatena os erros na mensagem, e o handler REST e o `mapearMensagemErro` do SOAP os repetem em `detalhes` / "Detalhes:". A mensagem sai duplicada.

### 7. `CertificadoA1` é recriado a cada requisição

`CertificadoProvider` lê o arquivo e cria um novo `CertificadoA1` por chamada, descartando o cache de KeyStore e chave privada. Ninguém chama `close()`. Para certificado vindo do servidor, cacheie a instância (invalidando por data de modificação do arquivo, para renovação anual). Para certificado via header, use try-with-resources. Os caches estáticos de `SSLContext` e `HttpClient` não têm limite nem expiração, o que é um risco se `allowHeaders` for ligado.

### 8. Registro durável só grava sucesso

Se o timeout ocorrer e a reconciliação falhar, nada fica registrado, e é justamente o caso em que o ERP precisa recuperar. Sugestão: gravar `PENDENTE` (idDps, correlationId) **antes** de transmitir e atualizar depois. Também, `buscarPorIdDps` e `listarUltimas` fazem varredura completa do JSONL **segurando o mesmo lock** das gravações, o que bloqueia emissões com o arquivo grande. Considere um índice em memória carregado na subida, ou rotação diária.

### 9. `extrairXmlDps` decodifica entidades de forma incondicional

Se o envelope já traz `<DPS>` em claro ou em CDATA e um texto legítimo com `&lt;` (ex.: `xDescServ`), o `replace` global corrompe o conteúdo. Só decodifique quando **não** houver `<DPS` nem `<infDPS` no payload bruto. A versão 1.00 → 1.01 só deveria ser reescrita no SOAP por causa de `IBSCBS`; no REST essa regra não existe, então centralize em um lugar só.

### 10. Hardening

- `ApiKeyAuthFilter`: use `MessageDigest.isEqual` (comparação em tempo constante). O `?api_key=` aparece em access log do Tomcat e do proxy; restrinja ao Swagger.
- Sem `NFSE_API_KEY`, a API opera aberta. No perfil `prod`, falhe a subida ou ao menos emita WARN forte.
- `application.properties` deixa `logging.level.br.com.heviane.nfse=DEBUG` também em produção; ponha INFO no `application-prod.properties`.
- `CorrelationIdFilter` aceita qualquer valor do cliente; valide `[A-Za-z0-9._-]{1,64}` (ele vai para log, JSONL e mensagem SOAP).
- `/health` custom fica atrás da API key, enquanto `/actuator/health` é público. Tire a duplicidade e a versão hardcoded.
- 401 no SOAP: os testes fixam 401, mas o pilar do projeto é "sempre HTTP 200 para o GeneXus". Confirme com o cliente como o GeneXus reage.
- Resposta com status 105 sai como `Sucesso=false`; o ERP pode tratar como falha e reenviar. Documente o contrato (a idempotência por `Id` cobre o reenvio, mas a tela do ERP vai mostrar erro).

## 🟡 Documentação e repositório

- `cliente-001.md` §8 ainda cita "harmonização de `tpAmb`", e o diagrama usa `POST /ws/nfse`. O código rejeita divergência de `tpAmb` e o endpoint é `/prefeitura/notafiscal/nfse.asmx`.
- `SPEC-003` §4 só descreve `NFSE_CERT_BASE64`; atualize para `NFSE_CERT_PATH`.
- `pilares-arquitetura` referencia `docs/glossary.md`; o arquivo real é `docs/glossario-nfse.md`.
- O README promete substituição de NFS-e e DANFSe, que não estão implementados.
- O CNPJ `00000000000191` (do Banco do Brasil) segue em todos os samples. Troque por um fictício com DV válido, como `11222333000181`.
- `CertificadoTesteHelper` tenta `/certs/teste_a1.p12`, mas `.gitignore` bloqueia `*.p12` e `certs/`. No CI cai sempre no fallback do `keytool`. Ou versiona o `.p12` descartável com `!src/test/resources/certs/` e `git add -f`, ou remove o primeiro ramo.
- O OWASP Dependency-Check roda com `continue-on-error: true`, então nunca bloqueia. É aceitável por enquanto, mas defina um critério (ex.: bloquear CVSS ≥ 9 depois de estabilizar).
- A `NfseProperties.truststore` não é usada; `SefinSSLContextFactory` lê direto de `System.getenv`. Remova a propriedade ou use-a.
